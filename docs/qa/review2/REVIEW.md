## Score: 7/10

The backend layering is the best part of this wave: the challenges migration puts
enforcement in guard triggers that fire on the RPC's own insert as well as on a direct table
write, `can_enter_challenge` is a single predicate both RLS and the RPC call, every RPC is
parameterized with no dynamic SQL, and `enter_challenge` delegates rather than
re-implementing. reviewA's two P0s and both P1s are genuinely fixed. What holds this back:
one new public read path (`challenge_entries`) that does not apply `can_view_wave` the way
every other content table in this schema does, an account deletion that leaves every voice
recording in storage, and an atışma recorder that plays a Wave outside the single-`<audio>`
store and keeps that audio running out loud into the reply take.

## What is good

- **The challenges migration's layering.** `can_enter_challenge` is one predicate that both `challenge_entries_insert` RLS and `challenge_entries_guard` call, so the app, the policy and the trigger cannot drift. The guard's own comment — "triggers fire either way, unlike RLS, which the RPC's SECURITY DEFINER bypasses" — is exactly the right reasoning, and `enter_challenge` really does delegate rather than re-implement. `challenge_picks_guard` refusing a pick for a Wave that never entered is a genuinely thoughtful integrity check most people would have skipped.
- **No SQL injection anywhere in 504 lines of new SQL.** Every RPC is `plpgsql`/`sql` with parameterized predicates, no `execute`, no string-built queries, `search_path` pinned on every function, and the forgiving cursor parser wraps its casts in an exception block instead of trusting the input.
- **Server Action discipline held.** Every action in `challenges/actions.ts` parses with Zod, checks the session, checks suspension and returns `{ ok, ... }` — with `requireModerator` layering on top of `requireSignedIn` rather than duplicating it. `isRateLimitError` is adopted on the new rate-limited table, exactly what the Stage 14 audit asked future call sites to do.
- **`20260905140000` is an honest bug-fix migration.** It names the failure ("failed live with violates check constraint"), fixes it in a new timestamped file with a matching `down/`, and the `down/` for the 504-line challenges migration drops every function, trigger, table and type in reverse dependency order.
- **Resource lifecycle in the new audio layer.** Every `URL.createObjectURL` in the repo has a matching `revokeObjectURL` in the same `useMemo`/cleanup pair (`ReviewStage`, `TakeStrip`, `EnhancementPicker`, `AudioPreview`), and every `AudioContext` constructed in `src/lib/audio/**` is closed in a `finally` or a `destroy()`. `RecordStage` deliberately passes `createAudioContext: () => null` so the monitor owns the only context on the screen, with the reasoning written down.
- **`PersistentPlayer` respects the single-store invariant.** `useWaveControls` is pure `useCallback`s, so mounting it three times (the `AppShell` probe plus both strips) creates nothing; `isBackingTrackId` correctly refuses to claim a reference track as something the reader is listening to; and it hides itself on the Wave's own detail page rather than double-rendering the transport.
- **The analytics rebuild.** The three-across metric-card grid and the pill range switcher are gone (§12.29, §12.4), and every figure is `type-mono tabular-nums` — the screen DESIGN.md names as the reference for what not to do now reads correctly.
- **`RecordStage`'s honesty about state.** Dormant ticks rather than a fake waveform before capture, "Nothing is saved yet" while live, a real message at the auto-stop cap, a wake lock while recording, `stopBecauseHidden` on `visibilitychange`/`pagehide` so a backgrounded tab keeps the audio instead of truncating it, and an `aria-live` status for every transition.
